我们的倒排表占用内存很大，求交时又需要快速跳过不匹配的文档号。请从零实现一个倒排表压缩与跳表求交组件。仓库目前只有一个空的 Maven 工程（pom.xml 只声明 JUnit 5 与 AssertJ）。要求：1) 倒排表文档号按升序保存，使用差值加变长整数编码压缩（说明编码规则）；2) 支持解码读取，并支持跳表结构：每若干个文档号记录一个跳表项（文档号与偏移）；3) 实现两表求交：利用跳表快速跳过不匹配区间，不得退化为逐条比较，需说明复杂度；4) 正确性：求交结果与逐条比较完全一致，需用随机倒排表大规模验证；5) 支持多表求交（三个以上）并说明处理顺序对性能的影响；6) 支持并发求交：多个查询并发执行不得破坏压缩数据；7) 提供统计：压缩前后字节数、解码次数、跳表跳跃次数与求交耗时；8) 测试覆盖编码解码往返、跳表求交正确性、多表求交、并发求交与压缩率数据；`mvn -q verify` 一条命令跑通。

## 实现说明（A 分支）

代码位于 `src/main/java/com/example/gsb/postings/`。

### 编码规则（差值 + VarInt）

- 文档号严格升序、去重（构造时校验）。
- 按块组织，默认每 32 个文档号一块；每块记录一个跳表项 `(锚点文档号, 压缩流偏移)`，
  锚点为该块首文档的绝对值，偏移指向它在压缩字节流中的位置。
- 块内首文档存绝对值，后续存差值 `d = doc[i] - doc[i-1]`（≥1），使各块可从偏移独立解码。
- 所有整数用 LEB128 变长编码（`VarInt`）：二进制每 7 位一组，低组先发，
  非末组最高位置 1。`128 → 0x80 0x01`，`300 → 0xAC 0x02`；小差值通常 1~2 字节。

### 解码与跳表定位

- `PostingsCursor` 游标式 `next()` 顺序读取；块内惰性解码到 32 元素的小缓冲。
- `advanceTo(target)`：先在跳表锚点数组上二分（O(log 块数)），再至多解码扫描
  一个候选块即可定位；被整体越过的块只比较锚点、完全不解码块内数据。
- 对压缩数据（`CompressedPostings`）构造后不可变、零可变字段，游标为每查询各自创建的
  一次性对象，因此多线程并发共享同一份压缩表天然安全。

### 两表求交与复杂度

追赶式合并（`Intersector.pairIntersect`）：比较两游标当前文档号，落后方调用
`advanceTo` 整段跳跃而不是逐条 `next`，因此不会退化为逐条比较。

- 跳跃定位：O(log(m/B) + B)，B 为块大小；
- 总体比较/解码量为 O(匹配块扫描 + 跳跃次数·O(log 块数))，稀疏不匹配区间被整块跳过；
  最坏（两表完全重叠）仍为 O(n+m)，这是输出完整交集所需的下界。

### 多表求交（3 张以上）与顺序影响

先按表长 df 升序排序，先对两张最短表求交，再用其（单调缩小的）中间结果依次去更长的
表上跳跃匹配。长表上的 `advanceTo` 次数由最短表候选数决定；若用长表驱动短表，df 悬殊时
会多出数量级的无谓跳跃（shortest-first / adaptive 优化）。乱序传入不影响结果正确性。

### 统计

- 压缩：`rawBytes()`、`compressedDataBytes()`、`skipBytes()`、`compressedBytes()`、
  `compressionRatio()`。
- 求交（`IntersectionResult`）：`decodeCount`（解码的 VarInt 数）、
  `skipCount`（被整体跳过、未解码的块数；中间结果流上为二分跳跃次数）、
  `elapsedNanos/elapsedMillis`。
- 实测稠密表（间距均匀 1~100，B=32）压缩率约 33%（2,000,000 文档 / 8MB 原始数据）。

### 测试覆盖（`src/test/java/...`，`mvn -q verify`）

- `VarIntTest`：已知编码字节、长度一致性、10 万随机值往返、截断/负数拒绝。
- `CompressedPostingsTest`：空表、升序校验、200 组随机往返、多种块大小、
  1000 次随机 `advanceTo` 对照线性二分、next/advanceTo 交错。
- `IntersectorTest`：手工小例、空/单/不交集合、300 组大规模随机两表（正反两种参数顺序）
  对照朴素双指针、100 组 3~7 表随机多表、稀疏场景断言跳表确实发生且解码量远小于表长。
- `ConcurrentIntersectionTest`：16 线程 × 50 查询共享压缩表并发求交，逐结果校验且
  结束后压缩数据完好。
- `CompressionStatsTest`：压缩率数据与阈值、统计一致性、解码/跳跃计数器。
